> 2026-10-12。用户要求继续 P2，并参考 NeoForge 官方移植指南。

## 1. 结果

- 新增玩家状态 Attachment，持久化、死亡/End clone 深复制、原生 S2C 同步；固定 StreamCodec 26 字节，没有新增客户端可改服务器状态的 C2S 包。

- 实现旧完整/破损光环伤害倍率、护甲前上限、免伤、临时保护、复活及冷却、下界回血、陨石、巨柱保护、药效限制、Lich 模式消耗。

- 不访问用户游戏实例，不提交或推送 Git。修改均保持本地，HEAD 仍是此前提交。

1.21.1 官方网页仍描述“附件需要手动发包”。但是本项目使用 **NeoForge 21.1.259**，其实际 class 和 patched 源码已有：

- `IAttachmentHolder.syncData`；
- 自动 initial/get/set/remove 同步，mutable 对象修改后需显式 `syncData`；
- 序列化与 `copyOnDeath` 的默认深复制。

已用 `javap` 以及 `build/neoForm/neoFormJoined1.21.1-20240808.144430/steps/transformSource/transformed/net/neoforged/neoforge/attachment/` 核验，不凭文档缺项重复实现网络系统。

因此 metadata 最低 NeoForge 版本从 `[21.1.0,)` 收紧为 **`[21.1.259,)`**：这是本次验证的最低保证版本，不声称更早补丁具备该 API。MC 仍是目标 1.21.1。

## 3. 原行为合同与实现方式

### 3.1 数值与时机

| 场景 | 本批保留的旧 fix2 行为 |
|---|---|
| 破损光环 | 主世界倍率0.85；下界0.7 |
| 完整光环 | 主世界0.75；下界 Player 入口额外0.5，再护甲前0.5，总0.25 |
| 同时装备两个 | 两个独立if连乘，不擅改互斥；主世界0.85×0.75 |
| 完整伤害上限 | 默认20，**在护甲、抗性、附魔、吸收前**，不是最终扣血上限 |
| 虚空 FELL_OUT_OF_WORLD | 跳过护甲前光环倍率/上限；原 Player 下界额外入口倍率没有void条件，本批同样未新增 |
| 临时保护 | invul>0且配置true，非void免疫；配置false则Player入口倍率0.2 |
| 常规免伤 | 完整Halo的爆炸、火、熔岩、窒息、摔落、挤压、溺水 |
| 复活 | 半最大血；HaloRvvCooldown=36000、RvvMeteorTime=6000、PurpleInvulnerableTime=400；生成原WitherServant召唤圈 |
| 图腾/void复活 | 原RETURN注入不检查原返回值、不排除void，因此图腾已成功消耗后仍会启动Halo复活，void亦可启动。**没有默默改优先级或安全规则。** |
| Tick | 服务端一次推进；invul照常减；完整Halo摘下后复活/陨石冷却冻结；存档中负值不擅clamp |
| 下界回血 | 装备完整Halo且alive，每25tick heal0.8 |
| 陨石 | 装备且meteoring>0、非旁观者，每20tick天顶条件满足时由服务器生成玩家归属NetherMeteor；雷雨与原时长保留 |
| 巨柱 | 原无ordinal getTrueOwner钩子按实际调用点刷新invul10、每25tick heal0.8；当前目标同方法有两次调用，测试记录回血1.6而不静默合成一次 |
| 物品消耗 | Goety Lich mode下消费已装备完整Halo，未把背包光环任意移除 |

伤害迁移不能只改成 `LivingDamageEvent.Pre`：这个新事件已经在护甲后；Incoming 在盾和无敌帧差额前。这里采用严格 require=1 的窄 Mixin，Player入口与两类 actuallyHurt 分开定位，并更新真实 DamageContainer。Player override 不会再次调用 LivingEntity actuallyHurt，所以不叠加两次护甲前光环规则。

### 3.2 状态保存和同步

`state/HaloState.java` 保留原 GRPlayerCapability 键：

- `PurpleInvulnerableTime`、`HaloRvvCooldown`、`RvvMeteorTime`；
- `OdamaneExpandedFlags`、`ArmorClimbing`（缺键默认true）、`ExtraMagicShield`、`PreparingEndRitual`、`spectreDarkmageMagicShieldCooldown`。

后五项先保存/复制以免扩展数据丢失，不宣称相关Odamane/装备功能已实现；未知NBT字段保留于本地持久化，网络只传固定已知字段。

附件注册ID：`goety_neorevelation:halo_player_state`，每实体不同对象；`copyOnDeath` 深复制不共享计时器；不再手工Clone重复累加。同版本server-client使用原生追踪/初始同步合同，mutable更新调用 `syncData`。

旧命名能力 `ForgeCaps/goety_revelation:gr_player_cap` 提供定点导入：仅新附件尚未存在时读取，不用旧数据覆盖新附件。不递归猜其他cap路径；**此导入不等于1.20.1完整旧世界跨版本兼容验证**。

### 3.3 自定义凋灵仆从

- 原类继承Goety `Summoned`，并非原版WitherBoss；保留三头、目标逻辑、半血箭免疫、原回血/破坏/音效、下界之星掉落逻辑。
- legacy registry ID：`goety_revelation:wither_servant`，尺寸0.9×3.5、跟踪8。
- 注册属性保持原ModMain实际上使用的 `WitherBoss.createAttributes()`，最大血300、护甲4。
- 同步定义改Builder；原mob type改Goety IMobTyped/ModMobType与minecraft undead标签；不重新引入已删除的MobType。
- 四参spawn、新掉落/维度签名、Vec3 WitherSkull方向、ColorParticleOption粒子、新实体破坏事件。
- Invul保存重读；原数字entity target ID仅内存同步、不跨存档持久化，本批同样不会把旧ID误保存为永久目标。
- 客户端模型/renderer/半血能量层和注册事件接入，独立服务端可加载公共代码。

1. GameTestHelper没有assertNotNull，用实际assertTrue非空API。
