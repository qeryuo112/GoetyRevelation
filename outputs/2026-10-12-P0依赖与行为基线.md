## 3. 库依赖能力分类与处理边界

补丁直接 import 涉及 **90 个不同 Ending Library 类/内部类、162 个 Java 文件**。本地 594 个 Library Java 中均可定位这些 import 的宿主编译单元，没有缺失类源；同版本字符串不保证最新 Git 源码与原产物实际库方法行为完全一致。

| 能力 | 代表依赖/旧实现 | 移植处理 |
|---|---|---|
| 加载、ASM 与条件 Mixin | `IClassProcessor`、`InjectionFinder`、`ApplyCheckMixinConfigPlugin`；反射写入 ModLauncher plugin map | 新工程选择最终实现并显式条件隔离，不把清空旧 Mixin 的启动器照搬；目标方法与插件条件按实际安装组合核验 |
| 状态、序列化与同步 | `SynchedCapabilityData`、`CapabilityEntityData`、能力 provider/typed data | 逐字段映射 NeoForge Attachment、序列化和 payload；生命周期、死亡复制、追踪同步不可省略 |
| 时间停止与调度 | 时间/实体更新 API、ServerTaskManager、客户端时钟与专用数据 | 独立移植核心时间规则及主线程调度；不是用“取消一个 Tick 事件”就等价 |
| 物品、伤害与实体 | 物品标签保护、Living/Entity helpers、事件契约 | 先迁当前模块实际消费的能力；防止与新版 Goety 伤害规则重复叠加 |
| 客户端 UI、字体、Shader | GUI、渲染/字体事件和扩展 helper | 客户端独立加载；顶点、GLSL、Uniform/AT、重载必须单独测试 |
| 动作与网络 | Packet/animation/sound 等 | 明确 C2S/S2C、StreamCodec、主线程与权限校验；补丁自身 13 次旧 SimpleChannel 注册已列清单 |
| 工具与可选兼容 | SafeClass、注解、其他模组桥接 | 无可选模组时不加载其类；保留 ModDepends/NoModDepends/DevEnv 条件，不加入伪装成功的 require=0 |

**本批两个光环物品、正常注册和七项配置不需要运行时 Library。** 但完整产物仍然依赖上述 Library 能力：第一批暂不添加旧 Forge jar，不等于整个库已被替代、可以从完整目标中删除。

## 4. 首批真实行为合同

### 4.1 两个光环

- 注册 ID：`goety_revelation:ascension_halo`、`goety_revelation:broken_halo`。
- 堆叠上限均 1；完整 EPIC、破损 RARE；不可附魔。
- Fix 的两个构造器 WrapOperation 增加 `fireResistant()`。
- 完整光环 Shift 优先：12 条 `tip1..tip12`；否则 Alt：19 条 `tip1.ability..tip19.ability`；默认两条灰色提示最终为 `tooltip.revelationfix.holdAltEffect` 和 `tooltip.revelationfix.holdShift`。
- 破损提示为 `tooltip.goety_revelation.tip13`。
- 公共物品类不读 `Screen`；按键提示交给客户端路径。

证据：外层 `decompiled/z1gned/goetyrevelation/item/{AscensionHalo,BrokenAscensionHalo}.java`；补丁 `reference/revelationfix-mapped/com/mega/revelationfix/mixin/gr/{AscensionHaloMixin,BrokenAscensionHaloMixin}.java`。

### 4.2 Library 的隐式掉落物合同

外层资源 `data/ending_library/tags/items/invulnerable_item.json` 将两个光环纳入库的保护标签。库 `mixin/ItemEntityMixin.java:27-43` 提高健康、将寿命设为 `Integer.MAX_VALUE`，并限制非 bypass 伤害；外层仍保留的 ItemEntityMixin 对这两个光环无条件 `hurt=false`，包括 bypass 来源。因此首批不能只用 fireResistant 宣称等价。

首批用窄范围的新 Mixin 保留这两个光环掉落实体的伤害保护与寿命能力；不扩大到标签内所有暂未移植物品。高龄掉落、虚空/爆炸/普通伤害、非光环控制组必须实际 GameTest。佩戴后的战斗、复活、冷却不属于此物品实体保护，也不在首批实现中。

### 4.3 配置初始化与范围

原 ModConfig `<clinit>` 的七次 define 全在 push("General") 之前：实际键是根级，不是 General 组。最后执行 build；迁移不增加组前缀。补丁默认健康 666，并将手动 loadConfig 覆写为空。新工程使用 ModContainer/NeoForge 生命周期，不再手工覆盖配置文件。

| 根级键 | 完整产物默认 |
|---|---:|
| player_invincible | true |
| player_ambient_sound | true |
| hellfire_damage_amount | 0.0444 |
| hellcloud_damage_amount | 0.001 |
| apollyon_health | 666.0 |
| apollyon_hurt_limit | 20.0 |
| summon_apollyon_random_value | 100，范围 1..2147483647 |

配置文件名保持 `goety_revelation.toml`。此批先恢复注册、载入、根级键与默认值；相应战斗能力尚未消费全部配置，不以配置可读代替玩法已实现。

## 5. 注册与资源的新增证据

- 外层第五注册路径由 `wither_quietus_focus` 改为 `revelation`；但是 **Fix GRItems.init 再次注册了 `wither_quietus_focus`**，它绑定真正的 WitherQuietusSpell。完整目标须保留两项，不是把旧 path 全量删除。
- GRItems.init 已提取 71 个字面 `ITEMS.register` 调用点。两个 block-item helper 使用原 block path 注册 `goety_revelation:rune_reactor` 与 `goety_revelation:runestone_engraved_table`；EnigmaticLegacy 存在时另注册 `goety_revelation:blessing_scroll`。证据：`common/init/GRItems.java:308-309,357-359`、`ModBlocks.java:19-30`、`common/item/curios/enigmtic_legacy/EnigmaticLegacyItemInit.java:21-24`。71 是字面调用点数，不冒充实际 runtime registry 总数。
- 原/内嵌包 assets/data 同路径交集：16 个内容一致，2 个内容不同。不同的是 `data/curios/tags/items/head.json` 和 `data/minecraft/tags/items/music_discs.json`。实际 pack 优先级尚未证明，单包迁移必须按 tag 合并语义重建，不能用覆盖包字节的方式漏掉值。
- 语言资源按所需键合并；只提取首批两个物品相关模型、贴图和提示，不载入依赖尚未注册物品的整包配方。
- 补丁 common 列表直接 import 客户端类的候选包括 ClientLevel、JEI ritual GUI 与 Tetra GUI；它们已进入隔离风险清单，不自动搬进 common 配置。
- 世界记录入口 `safe/GRSavedDataExpandedContext.java:36-39` 改为主世界 shared SavedData；不是外层历史的下界独立 storage。补丁扩展更多字段。本批不迁死亡奖励/世界记录，后续必须以此为准。
