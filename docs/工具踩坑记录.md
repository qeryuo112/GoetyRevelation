# 工具踩坑记录

> 依 RULES 第 7 条：记录工具使用中的错误、坑与最终改正方案，避免重复踩坑。

---

## E1. `maven.neoforged.net` 被 DNS 污染，Gradle 拉不到 NeoForge 依赖

- **现象**：`curl https://maven.neoforged.net/releases/` 返回 `000`；`getent hosts` 返回 Facebook 段 IP（`69.63.176.143` / `2a03:2880:...`）
- **诊断**：用 DoH 查真实 IP
  ```bash
  curl -s "https://dns.alidns.com/resolve?name=maven.neoforged.net&type=A"
  # → 173.255.209.47
  ```
- **试过但无效**：改 hosts 硬绑真实 IP —— TCP 层同样被阻断，仍超时
- **改正**：走本机 Clash 代理 `127.0.0.1:7897`，写入 `~/.gradle/gradle.properties`：
  ```properties
  systemProp.http.proxyHost=127.0.0.1
  systemProp.http.proxyPort=7897
  systemProp.https.proxyHost=127.0.0.1
  systemProp.https.proxyPort=7897
  ```
- **影响面**：`github.com`、`raw.githubusercontent.com` 直连同样不通；`api.github.com`、Maven Central、`services.gradle.org`、`maven.minecraftforge.net`、`piston-meta.mojang.com`、`maven.parchmentmc.org` 直连正常

## E2. Edge 155 禁止用默认 profile 开远程调试

- **现象**：`--remote-debugging-port=9223` 配默认 `user-data-dir` 时，端口**静默不开**
- **改正**：把 profile 复制到 `/tmp` 再用 `--user-data-dir=<副本>`
- **附带坑**：Linux 下 cookie 由 OS keyring 加密，必须**在同一用户会话**（`DBUS_SESSION_BUS_ADDRESS` 可用、keyring 已解锁）里启动，否则 cookie 解不出来 → 表现为"未登录"
- **验证登录是否生效**：读 `<meta name="user-login">`

## E3. 后台进程在单条 Bash 命令结束时被回收

- **现象**：`nohup microsoft-edge ... &` 起的实例，在下一条命令里 `curl 127.0.0.1:9223` 报 `ECONNREFUSED`
- **改正**：把「复制 profile → 启动浏览器 → 驱动脚本 → 收尾清理」**放在同一条命令里**；或用 `run_in_background` 整体托管

## E4. GitHub 敏感操作触发 sudo 二次验证，无头自动化做不完

- **现象**：添加 SSH key 时页面跳到 "Confirm access"，要求重输账号密码
- **改正**：以**非 headless** 启动浏览器（窗口出现在用户屏幕上），脚本把表单填好并提交后**停住轮询**，用户只需在窗口里输密码；脚本检测成功后继续后续动作（如 push）
- **适用范围**：加 SSH key、建 PAT、改账号设置等

## E5. `present_files` 工具持续报错

- **现象**：`Cannot convert argument to a ByteString because the character at index 14 has a value of 29305`
- **排查**：去掉 `explanation`、去掉 `cwd`、只留 `files` —— 均无效
- **判定**：会话级问题（疑似会话上下文中模型名含非 ASCII 字符，导致 MCP 参数编码失败），非参数问题
- **改正**：改用文字描述交付物清单，不再重复重试

## E6. 用户提供的凭据无效

- **输入**：一个 43 位随机串（自称 ssh 密钥，具体值已从本文档移除）
- **验证方法**：
  ```bash
  curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer <T>" https://api.github.com/user
  # → 401 Bad credentials
  ```
- **判定**：既不是有效 GitHub token，也不是 SSH 公钥（公钥应以 `ssh-ed25519` / `ssh-rsa` 开头）
- **改正**：本地生成 ed25519 密钥对替代。**该字符串不要再当作任何凭据使用**

## E7. 外层反编译范围不等于完整 JarJar 产物

- **现象**：只统计外层 112 class / 93 Java，遗漏了内嵌 RevelationFix 4.7 的 878 class 与 220 个配置 Mixin，导致全量移植工作量和行为来源判断偏小。
- **改正**：只读递归检查 JarJar metadata、嵌套 jar 的 mods.toml/Mixin plugin/必需依赖；核查补丁清理、替换和取消的逻辑，分别统计配置数、class数、条件启用数。不能拿配置数量当运行注入数。

## E8. javap 只看方法体会误判 Mixin 修改目标

- **现象**：看到 gr.ModItemsMixin 返回 revelation，曾误判为物品 namespace 改变。
- **实证更正**：`javap -p -c -v` 展示 @ModifyArg 目标为 DeferredRegister.register(String,Supplier)，ordinal=4、index=0，只改第五次物品注册 path（wither_quietus_focus → revelation），namespace不变。
- **改正**：必须把字节码、目标描述符、ordinal/index和外层注册顺序一起核查；方法名不能替代注解证据。

## E9. Vineflower 会失真静态初始化顺序

- **现象**：反编译 ModConfig 把 SPEC=BUILDER.build() 提到配置定义之前。
- **实证更正**：原 class 的 <clinit> 先 define 全部配置项，最后才 build。不能把它判为原 mod bug，也不能直接照抄。
- **改正**：关键 <clinit>/复杂switch/枚举扩展回查 javap 并写回归测试；SRG残留为0仅代表可读化，不代表语义等价。

## E10. NeoGradle dummy sources jar 不含实际源码

- **现象**：工作区 ng_dummy_ng/...-sources.jar 仅有manifest，易误判1.21.1源码缺失。
- **改正**：使用 build/neoForm/**/transformed、Gradle ng_execute/**/transformed 中的 MC patched 源码，以及 modules-2 中真正的 NeoForge sources.jar。核实版本再引用行号。

## E11. 分析协作的消息总结不是证据正文

- **现象**：子任务最终输出仅说矩阵已发送，调用方却未取得正文；任务完成状态不能替代实际可见证据。
- **改正**：要求最终 Response 包含具体矩阵；仍无法取得时由主代理直接复核原文件/字节码并标注未验证边界，不引用不可见结论。

## E12. SRG 映射 join 遗漏未混淆的类 owner

- **现象**：新反编译补丁残留 MinecraftServer 的 4 个方法符号、13 处使用；普通混淆类映射均命中。
- **根因**：ProGuard 类行右侧 `net.minecraft.server.MinecraftServer` 使用点分隔，joined.tsrg 同 owner 使用斜杠。成员键未规范化，owner 无法 join。
- **测试先行**：新增 `tests/test_srg_map.py` 合成未混淆 owner 测试，旧脚本失败（overworld 未命中）。
- **改正**：解析 ProGuard 类行时规范化内部 owner `.` → `/`，3 项测试通过；重建映射后补丁方法/字段 SRG token 残留 0。参数名保留，避免未经作用域分析的全局 argN 替换。

## E13. 配置分组和库标签不能凭源码表面推断

- **现象**：反编译源码尾部 push("General") 容易被重排为新配置的前置分组，导致原七项根级键变成 General.*。fireResistant 又容易被误当作完整光环掉落保护。
- **实证**：原 `<clinit>` 在 push 前完成全部 define；库资源 invulnerable_item 标签赋予不消失、掉落防伤能力，外层另有无条件 hurt 取消。
- **改正**：新配置保留根级键及补丁健康默认 666；光环掉落实体用专门测试覆盖任意 hurt 和高龄寿命，普通物品作为对照，不把仅耐火声明当全量保护。完整佩戴战斗能力另批实现。

## E14. Mixin 配置 required 与注入匹配 require 不是一回事

- **现象**：曾将 `require=1` 放到 `@Mixin`，这是不存在的元素；去掉后又误认为 JSON `required=true` 等价保证一次注入。
- **根因**：`required` 是配置失败策略；注入匹配次数门槛属于 `@Inject(require=1)` 或 JSON `injectors.defaultRequire=1`。缺少匹配门槛可能静默跳过真正玩法。
- **改正**：配置显式加入 neoforge.mods.toml `[[mixins]]`；官方 hurt 完整描述符、每个注入 require=1、defaultRequire=1、Java21。本批 remap=false 不声明并不存在的自动生成 refmap；实际伤害与普通物品控制组 GameTest 验证，不能仅看配置存在。

## E15. 独立游戏测试未覆盖掉落寿命及发布边界

- **现象**：基础六 GameTest 通过仍漏掉库标签的寿命能力、Age>=6000首次加载、测试类被打进正式 jar 和资源/数据 format 混用。
- **改正**：追加高龄5999/6000/32767、保存重读、普通石头6000 tick过期测试；寿命在tick HEAD保护以免TAIL之前已过期。jar排除开发测试类与empty.nbt；mod pack采用NeoForge ResourcePackLoader.OPTIONAL_FORMAT契约省略数字，分别按资源34/数据48加载，不声称独立包亦可省略format。

## E16. 版本化文档可能滞后于目标 NeoForge 补丁版本

- 官方1.21.1附件页仍说手工发包，但21.1.259的真实class与patched源码已有AttachmentType.Builder.sync/IAttachmentHolder.syncData回植。
- 处理：官方指南定位迁移方向，具体签名以锁定版本javap/源码为准。避免为文档没有写的API重复构建C2S和生命周期同步，记录最小依赖版本/证据。

## E17. 原减伤阶段不能机械替换成 Damage.Pre

- 原LivingHurt倍率/上限在护甲前；新LivingIncomingDamage在盾/无敌帧前，新LivingDamageEvent.Pre在护甲后、吸收前。Player还override actuallyHurt。
- 处理：Player入口Nether额外0.5定点ModifyArg；两个actuallyHurt前置调整实际DamageContainer，不只方法float参数；Player父类damageContainers通过extends LivingEntity访问，不能@Shadow一个非目标声明字段。

## E18. 真实行为测试必须有正确前置与调度

- Curios.findFirstCurio(Item)按当前gameTime缓存，装卸同tick可能返回过期槽位；改用无cache predicate查询，真实装卸freeze回归先失败再通过。
- 1.21.1吸收量受MAX_ABSORPTION上限约束，默认0；护甲测试先显式设上限、采用不bypass armor且不受开发环境PvP取消的生物攻击来源。不能把测试误设改成玩法数值。
- SummonCircle.tick直接调用不推进tickCount，通常由ServerLevel调度先increment；测延迟释放时按真实调度推进。所有权解析要求主人实际加入world UUID索引，不能只构造一个Player就断言解析失败是实现bug。
- 巨柱旧getTrueOwner注入未指定ordinal，会在多个调用点执行；不默认把多次0.8回血改成一次，按原selector保留并记录目标版本实际触发数。

## E19. 寿命保护误保留原版 /give 展示掉落物

- 真实反馈：库存得到光环，地面仍有不可拾取光环。GiveCommand先正常入背包，再drop展示副本并调用makeFakeItem：PickupDelay=32767、Age=默认实体寿命-1。本项目HEAD寿命MAX错误覆盖其一tick过期。
- 修复：同时识别永久拾取延迟与临近原版过期年龄，恢复原版寿命并跳过保护；兼容之前保存且Lifespan已被MAX覆盖的展示残影。普通高龄真光环/背包溢出真掉落仍不消失且可拾取，不把PickupDelay单独当假物品，不批量改存档。
- 证明：实际/give展示expires、库存count=1、满库存overflow后playerTouch可拾取、保存残影重读、真实高龄与fresh neverPickUp控制组。

## E20. 伤害复活测试通过不证明完整佩戴仇恨规则已迁移

- 手动日志证明8→6减伤及首次复活已生效，但漏了原Fix LivingEntity.canAttack的haloUndeadSuppression分支。默认true压制亡灵/LICH_NEUTRAL、Apostle例外；false仍压制不超过Goety阈值的弱亡灵。
- 补回canAttack窄注入及配置；不把亡灵压制改为永久无敌，不重置用户计时，不杜撰佩戴药水状态。
- 证明：实际WitherServant/Zombie.canAttack与TargetingConditions、真实运行目标Goal/三头AI、broken/backpack/spider/卸装控制、config false与使徒例外。原复活36000/6000/400不变。

## E21. GameTest模拟网络登录不等于已完成NeoForge/Curios握手

- makeMockServerPlayerInLevel在当前前置组合触发Curios登录sync时抛Payload curios:sync_data may not be sent to the client；这不是/give本身的bug。
- 命令测试用独立ServerPlayer与仅截获传输的连接执行实际命令/库存/实体逻辑，不发送伪网络流；明确不把它说成双客户端同步测试。

## E22. 重启型配置缓存与并行AI测试隔离

- worldRestart ConfigValue.set不立即更新cachedValue。测true/false分支显式clearCache并finally恢复，不移除worldRestart或修改玩法。
- 测仇恨解除必须先让真实TargetGoal运行，再佩戴，不能只setTarget制造没有Goal拥有的假前置。并行GameTest的未佩戴目标会被仆从正常攻击，AI测试隔离到无其他目标范围后再统计projectiles，禁止因邻近控制组被正常攻击而删玩法。
