## 候选路线

### A. 反编译移植（decompile → port）
用本地 Vineflower 反编译 112 个类 → 在 1.21.1 NeoForge 工程里修 API 变动 → 逐个重定向 mixin 目标。

- ✅ 保留原始逻辑与数值，行为最贴近原版
- ✅ 代码量小，工作量可控
- ⚠️ 反编译产物可读性差（泛型丢失、变量名退化），需人工整理
- ❌ **需确认授权**：All Rights Reserved 闭源产物，反编译+再分发在授权上有争议

### B. 资源复用 + 代码重写（clean-room）
只复用 assets/data（内容资产），代码按 1.21.1 规范重新实现。

- ✅ 规避反编译授权争议；代码质量与可维护性最好
- ❌ 需完全理解原 mod 行为；43 个 mixin 的精确逻辑极难复现
- ⚠️ assets/data 本身同样受版权保护，复用也需授权
- ❌ 工作量最大

### C. 混合：反编译当"行为说明书"，代码重写
参考反编译产物理解逻辑，但不直接使用其代码，重新实现。

- ✅ 兼顾行为准确性与代码质量
- ⚠️ 阅读反编译产物本身仍需授权
- 工作量介于 A 与 B 之间

### SRG 名处理（用户选择 A）

**用户选择（2026-10-12）：A —— 自建映射表并替换**

执行结果：

| 项 | 结果 |
|---|---|
| 反编译 | 本地 Vineflower 1.10.1 → `decompiled/`，93 个 .java，8312 行 |
| 映射表 | `tools/build_srg_map.py` 生成 **154329 条** SRG→官方映射（0 冲突） |
| 替换 | `tools/apply_srg_map.py` → **3045 处替换，0 残留，命中率 100%** |
| 效果 | 方法 SRG 595→0、字段 SRG 349→0、参数 SRG 290→0 |

**踩坑记录（详见 `docs/工具踩坑记录.md`）**
1. ProGuard 签名带行号前缀 `36:36:`，须先剥离，否则被当成返回类型
2. JVM 描述符用 `/` 分隔（`java/lang/String`），ProGuard 用 `.`（`java.lang.String`）
3. `client.txt` 与 `server.txt` 有重复条目，候选数判断必须先去重
4. **SRG 名不是全局唯一的**（同一个 `m_9236_` 出现在多个类里）→ 只有当所有候选官方名一致时才可全局替换

**映射源获取方式（可复现）**
```bash
# MCP config (obf -> SRG)
curl -L -o mcp_config-1.20.1.zip https://maven.minecraftforge.net/de/oceanlabs/mcp/mcp_config/1.20.1/mcp_config-1.20.1.zip
unzip -p mcp_config-1.20.1.zip config/joined.tsrg > joined.tsrg
# Mojang 官方映射 (obf -> 官方)
#   client.txt: https://piston-data.mojang.com/v1/objects/6c48521eed01fe2e8ecdadbd5ae348415f3c47da/client.txt
#   server.txt: 见 1.20.1.json 的 downloads.server_mappings.url
python3 tools/build_srg_map.py joined.tsrg client.txt server.txt srg2official.tsv
python3 tools/apply_srg_map.py srg2official.tsv decompiled
```

**产物安全**：`decompiled/`、`decompiled-raw/`、`*.jar` 均已在 `.gitignore` 中排除。用户声明已获原作者许可；内嵌 Fix/Library/资源及公开源码、再分发的授权范围尚未单独确认，确认前不自动提交派生实现到公开仓库。
